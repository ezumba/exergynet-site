# Public Contract Address Registry — 2026-08-28

**Directive:** VP Sales Directive 006, §20/§21
**Purpose:** the single canonical list of every execution address (contract or operator wallet) referenced across ExergyNet's public surfaces, so that no executable package or page can carry an address whose status here is `RETIRED`, `UNKNOWN`, or incompatible with its claimed operation. This registry was built by grepping every public-facing file in `exergynet-site` and `exergynet-mcp-server` for address literals, then independently verifying each one's on-chain status via direct RPC/Blockscout calls made during this incident (not copied from any prior document without re-verification).

Machine-readable companion: [`public-contracts.json`](public-contracts.json) (this directory) — same rows, same statuses, intended for future CI to diff against.

## Notes

- **Demo/fixture data excluded.** `explorer.html`'s fallback demo rows (`payment_address` values like `0x6Bf1C7aE...`, `0xE4A2a1d1...`, and job IDs like `0x0101...01`) are explicitly labeled `"status":"DEMO DATA — SAMPLE ONLY"` in the page's own source and are not real deployed contracts or wallets — they are correctly disclosed as synthetic per the P0 fix already applied in Directive 003. They are not tracked here as if they were real addresses.
- **LNES04MembraneV2 and SovereignVerifier** (both explicitly self-labeled mock per `VAULT_LEDGER.md`) were not independently re-verified on-chain during this pass — their status is carried forward from the internal ledger, not freshly confirmed, and should be re-verified before being treated as current.
- **Open item:** `lnes06.html`'s link to `0xwork.org/agents/0xbd1e790f6040...` references the retired/compromised wallet as a third-party agent-marketplace profile identifier, not a payment target. It was not changed this pass — changing the URL would point to a *different* (unverified) agent profile rather than fix anything, since 0xwork.org's own record is keyed to that specific address. Flagged for Directive 007 to determine the correct handling with the external site.
