Memory Server

Persistent, content-verified memory for any Model Context Protocol client. Give Claude, ElizaOS, and other MCP agents long-term recall that survives across sessions — running locally on your own disk, or over the ExergyNet gateway.

What It Is

Memory as an MCP tool

The Model Context Protocol lets an agent call external tools through a standard interface. An MCP memory server exposes persistent storage and retrieval as those tools — so the agent can write what it learns and read it back later, without you hand-rolling a memory layer or stuffing history into the prompt. ExergyNet provides this as content-addressed memory: what you store is retrieved by the hash of its content, so the same query over the same committed state returns the same bytes, every time.

Two Deployments

Local or gateway

Local — Vanguard Memory Node (VMN)

A local stdio MCP server that runs on your own NVMe. No API key, no cloud round-trip, your data stays on your machine. The fastest way to add durable memory to an MCP client.

Gateway — MCP over HTTP

Why It's Different

Content-verified, not best-effort

  • Deterministic Same query, same committed state → same evidence window. No run-to-run drift.
  • Verifiable Every memory-query result carries a SHA-256 content hash you can check.
  • Bounded What reaches the model stays small as the store grows — memory, not prompt bloat.
  • Model-agnosticSwap the reasoning engine; the memory substrate is unchanged.
