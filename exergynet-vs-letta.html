This is a comparison across categories. Letta is a framework you build a stateful agent inside; ExergyNet is a substrate that sits under any agent or framework. Understanding that distinction is more useful than a feature race — and it's why the two can work together.

What Letta Is

A stateful agent framework

Letta, formerly the MemGPT research project from UC Berkeley, is an open-source framework for building stateful LLM agents. Its core idea is an operating-system-inspired memory hierarchy — a main context the model sees each turn, recall storage for recent history, and archival storage for long-term knowledge — with the agent managing its own memory through tool calls. It is a strong choice when you want a complete, self-managing agent runtime with transparent, self-editing memory built in.

The Core Difference

A framework vs. a substrate

Letta is where the agent lives: it owns the loop, the memory tiers, and the self-editing behavior. ExergyNet is not an agent framework — it is the persistent-state, evidence, and authority layer beneath whatever framework you use. Its retrieval is deterministic and content-addressed with hash-verifiable results, and it treats the authority to act as a separate, deterministic decision independent of the model. Because they occupy different layers, an agent built in Letta could use ExergyNet as its verifiable memory-and-authority substrate.

Choosing

When to use which

Choose Letta when…

You want a complete agent framework with self-managing, OS-style memory built in, and you're happy to build your agent within its runtime.

Choose ExergyNet when…

You want a framework-independent substrate for verifiable memory and separated authority — usable under Letta, ElizaOS, MCP clients, or your own stack.
