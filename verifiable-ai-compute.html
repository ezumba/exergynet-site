Proof & Settlement

Verifiable
AI Compute

When an autonomous agent acts on the result of a computation, it is trusting whoever ran it. Verifiable compute replaces that trust with a check: the result arrives with a cryptographic proof the agent — or a smart contract — can verify before acting or settling.

STATUS NOTICE

ExergyNet's compute-settlement layer is operating in testnet mode. This page describes the target verifiable-compute architecture. For which contracts currently enforce on-chain proof verification versus recording a receipt pending it, see On-Chain Proof.

The Problem

Agents act on results they can't check

An agent that outsources a computation — a model inference, a data lookup, a settlement calculation — normally has no way to know the result is correct. It trusts the provider. As agents begin to move value and trigger consequences on those results, "trust the provider" becomes the weakest link: a wrong or tampered result becomes a wrong transaction.

The Approach

Prove the result, then settle on it

ExergyNet's target model binds a computation to verifiable evidence: work is performed off-chain, and the result is accompanied by a proof that can be checked independently — by the agent, or on-chain by a verifier contract — before anyone acts on it. Settlement is gated on that verification, so an unproven or invalid result does not clear.

  • Compute Work performed off-chain, away from the agent's trust boundary
  • Attest Result accompanied by a proof designed for independent verification
  • Verify Checked by the agent or an on-chain verifier before it is acted on
  • Settle Settlement gated on verification — unproven results do not clear
Why It Fits Agents

Evidence bound to consequence

Verifiable compute is the same idea as ExergyNet's memory layer, applied to work instead of state: don't trust, check. Where agent memory makes retrieved evidence content-verifiable, verifiable compute makes computed results proof-verifiable — so the operations an agent takes on the world are backed by evidence, not by faith in a provider.
