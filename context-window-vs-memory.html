Concepts

Context Window
vs. Memory

"Just use a bigger context window" is the most common answer to agent memory — and the most misleading. A context window is working space for one request. Memory is state that persists across all of them. Confusing the two is why agents forget, and why prompts get expensive.

Definitions

Two different things

Context window

The fixed maximum number of tokens a model can read in a single request. It is temporary, per-call working space. When the request ends, it is gone. Everything in it is paid for — in latency and cost — every time you send it.

Persistent memory

The durable, growing body of what an agent has learned and done, held outside any single request. It survives sessions and restarts, and it can grow far larger than any context window.

Why Bigger Windows Don't Solve It

Three reasons scale wins the argument

  • Hard ceiling Every model has a maximum. Past it, injecting the full history is simply rejected — the request cannot run.
  • Rising cost Re-sending accumulated state means paying prefill cost for the whole history on every turn. Growth compounds.
  • Signal loss As you pack more in, the relevant evidence competes with everything else. More context is not more precision.

A larger window raises the ceiling. It does not change the shape of the problem: if memory lives inside the prompt, its cost grows with everything the agent has ever accumulated.

The Principle

Decouple stored state from active context

The scalable move is to stop treating accumulated state and active context as the same resource. Let stored state grow without bound. For each query, resolve a small, relevant slice of it and hand only that to the model. The persistent corpus can expand indefinitely while what the model actually reads per query stays bounded by relevance, not by history.

Stored state grows. Active context does not have to. This is the design principle behind ExergyNet's agent memory: externalize the state, retrieve a bounded evidence window, keep the inference payload small regardless of how much the agent has accumulated.

For the measured behavior of active model-facing context as the underlying corpus scales, see Benchmarks & Evidence.

What This Enables

Small prompts, long memory

When state is externalized, an agent can accumulate an effectively unlimited history while each inference call stays lean and predictable. Cost stops tracking total history and starts tracking per-query relevance. The accelerator processes a bounded evidence window instead of an ever-growing transcript — which is the difference between an agent that scales and one that hits a wall.
