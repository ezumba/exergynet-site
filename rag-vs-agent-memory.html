RAG vs.
Agent Memory

They are often confused, but they solve different problems. RAG pulls relevant documents into a prompt to answer a question. Agent memory persists an agent's own evolving state — what it has learned, decided, and done — across sessions. Most real agents need both.

Definitions

Two jobs, not one

RAG / vector search

Retrieval-augmented generation embeds a corpus of documents and, at query time, pulls the semantically nearest chunks into the prompt. It is a way to ground answers in a knowledge base — typically read-only reference material the agent did not author.

Agent memory

Persistent memory is the agent's own accumulated state — prior decisions, outcomes, and evidence — written by the agent and read back later. It is durable, it evolves with the agent, and it must stay consistent across sessions.

Choosing

When to use which

Reach for RAG when…

You need to answer questions over a body of reference documents — docs, tickets, a knowledge base — and approximate semantic recall is exactly what you want.

Reach for agent memory when…

The agent must remember its own history reliably across sessions, you need the same query to return the same evidence every time, and you want that evidence to be verifiable rather than best-effort.
